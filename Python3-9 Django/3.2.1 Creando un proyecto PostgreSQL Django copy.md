# Creación de un Proyecto Django con PostgreSQL

## 1. Creando el Primer Proyecto Django (Local)

Para crear un nuevo proyecto Django, sigue estos pasos:

1.  **Abre la terminal o línea de comandos.**
2.  **Navega hasta la carpeta de trabajo** donde deseas crear el proyecto.
3.  **Ejecuta el siguiente comando:**
    ```bash
    django-admin startproject miProyecto
    ```
    Reemplaza `miProyecto` con el nombre que quieras darle a tu proyecto.

4.  **Se creará una carpeta llamada `miProyecto`** con la estructura de archivos inicial necesaria para tu proyecto Django.
5.  **Entra en la carpeta de tu proyecto** con `cd miProyecto`

### Estructura del Proyecto

Dentro de la carpeta del proyecto (`miProyecto`), encontrarás los siguientes archivos y carpetas importantes:  

* **`manage.py`:** Una utilidad de línea de comandos que permite interactuar con el proyecto Django para realizar diversas tareas (ejecutar el servidor de desarrollo, crear aplicaciones, ejecutar migraciones, etc.).
* **`miProyecto/` (carpeta interior):** Un paquete de Python que contiene los archivos de configuración del proyecto:
    * **`__init__.py`:** Un archivo vacío que indica a Python que este directorio debe ser tratado como un paquete.
    * **`settings.py`:** Contiene todas las configuraciones del proyecto Django, incluyendo la configuración de la base de datos, las aplicaciones instaladas, la configuración de las URLs, etc.
    * **`urls.py`:** Define las rutas (URLs) de la aplicación y las vistas (funciones que procesan las peticiones a esas URLs) asociadas.
    * **`wsgi.py`:** Un archivo necesario para desplegar la aplicación Django en un servidor web compatible con WSGI (Web Server Gateway Interface).

## 2. Configuración de PostgreSQL como Base de Datos en Django

Pra que las aplicaciones de Django funcionen, es necesario instalar la base de datos. Por defecto, Django utiliza SQLite, y el comando `python manage.py migrate` se encarga de crear la base de datos SQLite (si no existe) y aplicar las migraciones iniciales.

Para utilizar PostgreSQL en lugar de SQLite, se requieren los siguientes pasos:

### 2.1. **Instalar el Adaptador de PostgreSQL para Python:**
Django necesita un conector para interactuar con PostgreSQL. El adaptador más común es `psycopg2`. Puedes instalarlo usando pip. (En Windows se recomienda usar la versión -binary para una instalación más sencilla, ya que incluye las dependencias necesarias).  

```bash
pip install psycopg2-binary
```
Se recomienda la versión `-binary` para simplificar la instalación de las dependencias necesarias.  

Para comprobar:  
```bash
pip show psycopg2-binary
```
Nota: Si usas Django 4.2 o superior y prefieres la versión más moderna, instala `psycopg` en lugar de `psycopg2-binary`

### 2.2.  **Asegurarse de tener PostgreSQL instalado y configurado:**

Debes tener el servidor de PostgreSQL instalado y en funcionamiento. También necesitarás crear una base de datos y un usuario con los permisos necesarios para acceder a ella. Puedes hacer esto utilizando las herramientas de administración de PostgreSQL (como `psql` o `pgAdmin`).  

Web oficial de PostgreSQL [Página web de descarga: PostgreSQL](https://www.postgresql.org/download/).  

Ejecuta el instalador. Durante la instalación, se te pedirá que configures:  
- La ubicación de la instalación.
- El directorio de datos.
- Una contraseña para el usuario postgres (el superusuario por defecto). Recuerda esta contraseña.
- El puerto en el que el servidor PostgreSQL escuchará (el predeterminado es 5432).
- La configuración regional.
- El instalador también puede ofrecer instalar herramientas (Add-ons) como `pgAdmin`, una interfaz gráfica de administración. Es recomendable instalar `pgAdmin`.

## 3. Configuración de PostgreSQL: Creación de Base de Datos y Usuario

Una vez que PostgreSQL está instalado, puedes crear una base de datos y un usuario con los permisos necesarios utilizando la línea de comandos (`psql`) o la interfaz gráfica (`pgAdmin`).

### 3.1. Opción 1: Usando `psql` (línea de comandos):

1.  **Accede a la consola de PostgreSQL:**
    * Si configuraste una contraseña para el usuario `postgres` durante la instalación, puedes intentar conectarte directamente:
        ```bash
        psql -U postgres
        ```
        Te pedirá la contraseña.
    * En sistemas Linux donde se creó un usuario `postgres` en el sistema operativo, puedes usar `sudo`:
        ```bash
        sudo -u postgres psql
        ```

2.  **Crea una nueva base de datos:** Reemplaza `nombre_de_tu_base_de_datos` con el nombre que desees para tu base de datos Django:
    ```sql
    CREATE DATABASE nombre_de_tu_base_de_datos;
    ```

3.  **Crea un nuevo usuario (rol) para acceder a la base de datos:** Reemplaza `nombre_de_usuario_postgresql` con el nombre de usuario deseado y `'tu_contraseña_postgresql'` con una contraseña segura:
    ```sql
    CREATE ROLE nombre_de_usuario_postgresql WITH LOGIN PASSWORD 'tu_contraseña_postgresql';
    ```

4.  **Otorga permisos al usuario para la base de datos:** Para que el usuario pueda realizar operaciones en la base de datos, necesitas otorgarle permisos. El permiso `ALL PRIVILEGES` le da control total sobre la base de datos. Si prefieres permisos más específicos, puedes otorgar `CONNECT`, `CREATE`, `SELECT`, `INSERT`, `UPDATE`, `DELETE`, etc.:
    ```sql
    GRANT ALL PRIVILEGES ON DATABASE nombre_de_tu_base_de_datos TO nombre_de_usuario_postgresql;
    ```

5.  **Sal de la consola `psql`:**
    ```sql
    \q
    ```

### 3.2. Opción 2: Usando `pgAdmin` (interfaz gráfica):

1.  **Abre `pgAdmin`:** Busca en el menú de tu sistema o en la lista de aplicaciones.

2.  **Conéctate al servidor PostgreSQL:** Si es la primera vez que lo abres, es posible que necesites configurar una conexión a tu servidor PostgreSQL. Haz clic derecho en "Servers" y selecciona "Create" -> "Server...". Completa los detalles de conexión (nombre, host, puerto, usuario `postgres`, contraseña).

3.  **Crea una nueva base de datos:**
    * Expande el servidor al que te conectaste.
    * Haz clic derecho en "Databases" y selecciona "Create" -> "Database...".
    * Ingresa el nombre de tu base de datos en el campo "Database".
    * Puedes configurar otras opciones si lo deseas y luego haz clic en "Save".

4.  **Crea un nuevo usuario (rol):**
    * Expande el servidor.
    * Haz clic derecho en "Login/Group Roles" y selecciona "Create" -> "Login/Group Role...".
    * En la pestaña "General", ingresa el nombre del usuario (Role name).
    * En la pestaña "Definition", establece una contraseña para el usuario.
    * En la pestaña "Privileges", puedes otorgar permisos. Para dar permisos sobre una base de datos específica, puedes hacerlo después de crear la base de datos.

5.  **Otorga permisos al usuario para la base de datos:**
    * Expande "Databases".
    * Haz clic derecho en la base de datos que creaste y selecciona "Properties...".
    * Ve a la pestaña "Privileges".
    * Haz clic en el botón "+" para agregar una nueva entrada de privilegio.
    * Selecciona el usuario que creaste en el campo "Grantee".
    * Selecciona los privilegios que deseas otorgar (por ejemplo, marca todas las casillas para `ALL PRIVILEGES`).
    * Haz clic en "Save".

### 3.3. Verificación:

Después de seguir estos pasos, deberías tener:

* El servidor PostgreSQL instalado y en funcionamiento.
* Una base de datos creada para tu proyecto Django.
* Un usuario de PostgreSQL con una contraseña y los permisos necesarios para acceder y trabajar con esa base de datos.

Con esta configuración, podrás configurar Django para utilizar PostgreSQL como se explicó anteriormente, modificando la sección `DATABASES` en tu archivo `settings.py` con la información de la base de datos, el usuario y la contraseña que acabas de crear.

# 4. Configurar Django para usar PostgreSQL

Ahora que tienes un usuario y una base de datos configurados en PostgreSQL, sigue estos pasos para conectar Django:  

## **"NOTA IMPORTANTE:"** Ver tutorial recomendado en el archivo '[Mejorando la seguridad](3.2.2%20Mejorando%20la%20seguridad.md)'

Editar el archivo settings.py
Abre el archivo settings.py de tu proyecto Django y modifica la sección DATABASES:

```python
DATABASES = {
    'default': {
        'ENGINE': 'django.db.backends.postgresql',
        'NAME': 'nombre_de_la_base_de_datos',  # Nombre de la base de datos
        'USER': 'nombre_de_usuario',          # Nombre del usuario de PostgreSQL
        'PASSWORD': 'contraseña_segura',      # Contraseña del usuario
        'HOST': 'localhost',                  # Dirección del servidor PostgreSQL
        'PORT': '5432',                       # Puerto predeterminado de PostgreSQL
    }
}
```
Importante : Asegúrate de reemplazar los valores con los que configuraste en pgAdmin.

Con la configuración completa, es hora de aplicar las migraciones de Django para crear las tablas en PostgreSQL.  

**Ejecutar las migraciones**  

En la terminal, dentro de tu entorno virtual, ejecuta:  
```bash

Esto creará las tablas necesarias en la base de datos PostgreSQL.  

**Crear un superusuario (opcional)**  

Si necesitas acceder al panel de administración de Django, crea un superusuario:

```bash

```

## 6. Crear aplicaciones dentro del proyecto (opcional, pero común)

El comando `python manage.py startapp miApp` , donde miApp es el nombre de la aplicación a crear, es fundamental en el desarrollo de proyectos Django. Su función principal es crear una nueva aplicación dentro de tu proyecto Django existente.  

En el contexto de Django, una "aplicación" es un componente autocontenido que se encarga de una funcionalidad específica de tu proyecto. Piensa en ella como un módulo independiente que puede tener sus propios:  
- Modelos: Definiciones de las estructuras de datos de tu aplicación (cómo se almacenan y organizan los datos en la base de datos).
- Vistas: La lógica que procesa las peticiones del usuario y devuelve respuestas (a menudo mostrando datos a través de plantillas).
- Plantillas: Archivos HTML con lógica de presentación para mostrar información al usuario.
- Formularios: Clases para crear formularios HTML y procesar la entrada del usuario.
- URLs: Definiciones de las rutas web específicas de esta aplicación.
- Administración: Configuración para la interfaz de administración de Django para gestionar los modelos de esta aplicación.
- Migraciones: Cambios en los modelos que necesitan ser aplicados a la base de datos.
- Tests: Código para probar la funcionalidad de la aplicación.

### 6.1. ¿Por qué dividir tu proyecto en aplicaciones?

- Modularidad: Divide un proyecto grande y complejo en partes más pequeñas y manejables. Cada aplicación se enfoca en una tarea específica.
- Reusabilidad: Las aplicaciones bien diseñadas pueden ser reutilizadas en diferentes proyectos Django.
- Organización: Facilita la organización del código, haciendo que sea más fácil de entender, mantener y colaborar en el proyecto.
- Escalabilidad: Permite escalar partes específicas de tu proyecto de forma independiente si es necesario.

### 6.2. ¿Qué hace el comando `python manage.py startapp miApp`?

Cuando ejecutas este comando desde la raíz de tu proyecto Django (donde se encuentra el archivo manage.py), Django realiza las siguientes acciones:  
1. Crea una nueva carpeta llamada miApp (o el nombre que hayas especificado).
2. Dentro de esta carpeta, genera una serie de archivos Python esenciales para una aplicación Django básica:
   - \_\_init__.py: Un archivo vacío que indica a Python que este directorio debe ser tratado como un paquete.
   - admin.py: Donde registrarás tus modelos para que sean accesibles a través de la interfaz de administración de Django. Archivo necesario para que migrations sea un paquete.
   - apps.py: Contiene la configuración de la aplicación.
   - models.py: Donde definirás los modelos de datos de tu aplicación.
   - tests.py: Donde escribirás las pruebas unitarias para tu aplicación.
   - views.py: Donde implementarás la lógica de las vistas de tu aplicación.
   - migrations/: Una subcarpeta que contendrá los archivos de migración de tu aplicación (inicialmente estará vacía).

### 6.3. Después de crear la aplicación, hay que registrarla

Una vez que la aplicación ha sido creada, el siguiente paso importante es registrarla en la configuración de tu proyecto. Esto se hace modificando el archivo settings.py que se encuentra dentro de la carpeta de tu proyecto (la carpeta interior que tiene el mismo nombre que tu proyecto).

Dentro de `settings.py`, busca la lista llamada `INSTALLED_APPS` y añade el nombre de tu nueva aplicación como una cadena:
```python
# settings.py

INSTALLED_APPS = [
    'django.contrib.admin',
    'django.contrib.auth',
    'django.contrib.contenttypes',
    'django.contrib.sessions',
    'django.contrib.messages',
    'django.contrib.staticfiles',
    'miApp',  # Añade el nombre de tu aplicación aquí
]
```
Al registrar tu aplicación en `INSTALLED_APPS`, le indicas a Django que esta aplicación forma parte de tu proyecto y que debe tenerla en cuenta al ejecutar comandos, buscar modelos, cargar plantillas, etc.

# 8. Creando la Primera Página Personalizada: Vistas y URLs

## 8.1 Creando los módulos

Algunos de los elementos más comunes que incluye ese "etc." son:  

- `models.py`: Este archivo contiene las definiciones de las clases de modelo. Cada clase de modelo representa una tabla en la base de datos de tu aplicación. Los atributos de cada clase de modelo representan las columnas de esa tabla, definiendo el tipo de dato, restricciones (como longitud máxima, unicidad, etc.), y relaciones con otros modelos. Django utiliza estas definiciones para crear y gestionar la estructura de la base de datos.
- `views.py`: Este archivo contiene la lógica de las vistas de tu aplicación. Una vista es una función (o una clase basada en vistas) que recibe una petición HTTP (request) y devuelve una respuesta HTTP. La lógica dentro de una vista procesa la petición, interactúa con los modelos para obtener o modificar datos, y decide qué contenido enviar de vuelta al usuario (generalmente renderizando una plantilla HTML).
- `urls.py`: (Rutas/URLs) Este archivo define los patrones de URL para tu aplicación. Contiene una lista de mapeos entre las direcciones URL que los usuarios pueden visitar y las vistas que deben ejecutarse cuando se accede a esas URLs. Django utiliza este archivo para determinar qué vista debe manejar una petición HTTP entrante basándose en la URL solicitada.
- `admin.py`: Este archivo se utiliza para registrar tus modelos con la interfaz de administración de Django, permitiéndote gestionar los datos de tu aplicación a través de una interfaz web autogenerada.
- `forms.py`: Aquí defines las clases de formulario que se utilizan para manejar la entrada de datos de los usuarios en tus vistas.
- `serializers.py`: Si estás construyendo una API (con Django REST Framework, por ejemplo), este archivo contendrá las definiciones de los serializadores que convierten los objetos de modelo en formatos como JSON o XML, y viceversa.
- `tests.py`: En este archivo escribes las pruebas unitarias y de integración para verificar que tu aplicación funcione correctamente.
- `middleware.py`: Aquí puedes definir middleware personalizado, que son componentes que se ejecutan durante el procesamiento de las peticiones y respuestas en tu aplicación.
- `templates/` (directorio): Dentro de este directorio (y sus subdirectorios), almacenarás los archivos de plantilla HTML que se utilizan para renderizar la interfaz de usuario de tu aplicación.
- `static/` (directorio): Este directorio se utiliza para almacenar archivos estáticos como hojas de estilo CSS, archivos JavaScript e imágenes que son utilizados por tus plantillas.
- `signals.py`: Aquí puedes definir señales, que permiten que ciertas acciones ocurran cuando otras acciones tienen lugar en tu aplicación o en el propio Django.
- `apps.py`: Este archivo contiene la configuración de la aplicación, incluyendo su nombre y cualquier lógica de inicialización que necesite ejecutarse cuando la aplicación se carga.

Es crucial recordar que todos estos archivos (admin.py, forms.py, serializers.py, tests.py, middleware.py, signals.py, apps.py) y los directorios (templates/, static/) deben residir dentro de la carpeta de cada aplicación específica, y no directamente en la raíz del proyecto Django.  

## 8.2 Primera Página Personalizada

Django sigue el patrón MTV (Modelo-Template-Vista). Para crear una página personalizada, necesitaremos definir una vista (la lógica que procesa la petición y devuelve una respuesta) y una URL que mapee una dirección web a esa vista.  

1. Crea un archivo `views.py` dentro de la carpeta de tu proyecto (`miProyecto/`).  

2. Define una vista en `views.py`. Una vista es una función que recibe un objeto `HttpRequest` y devuelve un objeto `HttpResponse`. Por ejemplo:  
```python
# miProyecto/views.py
from django.http import HttpResponse

def saludo(request):
    return HttpResponse("Hola mundo")

def fecha(request):
    import datetime
    ahora = datetime.datetime.now()
    return HttpResponse(f"<html><body><h2>Fecha y hora actual:</h2> {ahora}</body></html>")

def calcEdad(request, year):
    edadActual = 18
    periodo = year - 2025 # Se corrige el año base
    edadFutura = edadActual + periodo
    return HttpResponse(f"<html><body><h2>En el año {year} tendrás {edadFutura} años.</h2></body></html>")
```
3. Define las URLs que apuntan a estas vistas.
3.1. Abre el archivo `miProyecto/urls.py` y modifica la lista `urlpatterns`:
```python
# miProyecto/urls.py
from django.contrib import admin
from django.urls import path
from . import views  # Importa las vistas desde el directorio actual

urlpatterns = [
    path('admin/', admin.site.urls),
    path('saludo/', views.saludo, name='saludo'), # Se añade 'name' para futuras referencias
    path('fecha/', views.fecha, name='fecha'),
    path('calcEdad/<int:year>/', views.calcEdad, name='calcEdad'), # Se especifica el tipo de dato del parámetro
]
```
- Asegúrate de importar tus vistas desde el archivo `views.py`.
- La sintaxis `<tipo:nombre_parametro>` en la URL permite capturar valores dinámicos y especificar su tipo (en este caso, `int` para un número entero).

3.2. Si las vistas están dentro de una aplicación del proyecto

- Crear un archivo urls.py dentro de la carpeta de tu aplicación PYworld (si no existe).

- Definir las rutas específicas de esa aplicación dentro de PYworld/urls.py
```Python
# PYworld/urls.py
from django.urls import path
from . import views  # Aquí el '.' se refiere al directorio actual de la aplicación PYworld

urlpatterns = [
    path('inicio/', views.mi_vista_inicio, name='inicio'),
    path('otro/', views.otra_vista, name='otra'),
    # ... otras rutas de la aplicación PYworld
]
```

- Incluir las URLs de la aplicación PYworld en el archivo miProyecto/urls.py:
```Python
# miProyecto/urls.py
from django.contrib import admin
from django.urls import path, include

urlpatterns = [
    path('admin/', admin.site.urls),
    path('', include('PYworld.urls')),  # Incluye las URLs de la aplicación PYworld
    # ... otras rutas a nivel de proyecto (si las hubiera)
]
```
La forma estándar es crear un archivo urls.py dentro de cada aplicación y usar include() en miProyecto/urls.py para incorporar las URLs de cada aplicación. Dentro del urls.py de cada aplicación, from . import views sí se refiere a las vistas definidas en el views.py de esa misma aplicación.  

4. Ejecuta el servidor de desarrollo (si no lo has hecho ya):

```bash
python manage.py runserver
```

5. Accede a las URLs en tu navegador:

- http://127.0.0.1:8000/saludo/ mostrará "Hola mundo".
- http://127.0.0.1:8000/fecha/ mostrará la fecha y hora actual.
- http://127.0.0.1:8000/calcEdad/2030/ mostrará la edad que tendrás en el año 2030.

# Pasando Parámetros por la URL

Django permite pasar parámetros dinámicos a las vistas a través de la URL. Esto se define en el archivo `urls.py` utilizando la sintaxis `<tipo:nombre_parametro>`. El valor capturado se pasa como argumento a la función de vista correspondiente.  

Ejemplo con dos parámetros:  

1. Modifica la vista `calcEdad` en `views.py`:  

```python
# miProyecto/views.py
from django.http import HttpResponse

def saludo(request):
    # ... (código anterior)

def fecha(request):
    # ... (código anterior)

def calcEdad(request, edadActual, year):
    periodo = year - 2025 # Se corrige el año base
    edadFutura = edadActual + periodo
    return HttpResponse(f"<html><body><h2>En el año {year} tendrás {edadFutura} años.</h2></body></html>")
`
2. Modifica las URLs en `miProyecto/urls.py`:  
```python
# miProyecto/urls.py
from django.contrib import admin
from django.urls import path
from . import views

urlpatterns = [
    path('admin/', admin.site.urls),
    path('saludo/', views.saludo, name='saludo'),
    path('fecha/', views.fecha, name='fecha'),
    path('calcEdad/<int:edadActual>/<int:year>/', views.calcEdad, name='calcEdad'),
]
```

3. Accede a la URL con los parámetros:  

`http://127.0.0.1:8000/calcEdad/25/2035/` mostrará la edad que tendrá alguien de 25 años en el año 2035.
Recuerda que los parámetros capturados en la URL se pasan a la vista en el mismo orden en que se definen en la URL. Es importante especificar el tipo de dato esperado (`int`, `str`, `slug`, `uuid`, `path`) para que Django pueda realizar la conversión adecuada y evitar errores. Si no se especifica el tipo, se asume que es una cadena (`str`).

## 9. Crear y aplicar migraciones para tus modelos.

Cuando modifiques tus modelos, necesitarás crear y aplicar migraciones para actualizar el esquema de la base de datos PostgreSQL:
```bash
python manage.py makemigrations miApp  # Reemplaza miApp con el nombre de tu aplicación
python manage.py migrate
```
